# Read Import Details through a Conversation-owned data seam

Import Details reads a committed Chat's import provenance on demand: the persisted import receipt, structured duplicate evidence, and exact-source artifact availability. The per-Chat read previously created its own Drizzle handle and opened the Conversation-owned `chat_data` table directly, so a change to how Conversation-scoped data is stored required the import module and the Conversation module to move together. The exact-source half was already behind the artifact seam; the conversation half was not.

We add one narrow public read to the deep Conversation seam: `readConversationData(conversationId, { namespace?, keys? })`, returning the Conversation name plus the matching (namespace, key) entries, and undefined for a missing Conversation. The read is vocabulary-free — namespace and key strings pass through uninterpreted — so the Conversation module keeps owning the schema locality of its own data while staying ignorant of SillyTavern import meaning. Import Details now composes its receipt solely through this seam plus the existing artifact seam; the cross-Chat prior-import duplicate scan stays a single owned import-domain query shared by the developer import, the staged preview, and Import Details.

This refines ADR-0024 ("domain modules keep owning their queries") and ADR-0013 (routes and cross-module workflows call public seams rather than writing Conversation tables directly) without superseding them. We deliberately did not give the Conversation module a first-class "import provenance" read (that would reintroduce a lasting imported subtype that ADR-0026 abolished), nor a generic cross-Chat key-value lookup (the generic repository interface ADR-0024 forbids). The import receipt semantics, duplicate classification, and artifact availability remain import-domain concerns.
