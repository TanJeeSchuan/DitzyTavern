# Compile Generation Plans through one seam

The server compiles each Generation through one deep Generation Plan Compiler interface after resolving the safe Connection facts needed to determine applicability. It accepts the complete canonical Generation Settings object and Generation intent, then returns a Generation Plan containing the provider-neutral Prompt Plan, budget decision, and Effective Generation Settings. Effective means that DitzyTavern used a value locally or supplied it to the selected Model Client adapter; it does not claim that a remote provider honored the value. Credentials, headers, and URLs never enter the Generation Plan or its provenance.

The pure Prompt Compiler from ADR-0014 remains internal implementation. It still owns named-block ordering, macros, normalized selected history, and future Prompt Manager behavior, while the outer compiler owns intent applicability, budgeting, active API Format selection for Request Overrides, and the complete plan consumed by Generation workflows. This replaces workflow-owned object reconstruction, which allowed settings capture, inspection, persistence, and Model Client projections to drift.

The canonical Generation Settings structure is a shared TypeBox schema. Compatible types and schemas derive from it; explicit adapters remain where database storage, provenance, update commands, or Model Client input have genuinely different semantics. These adapters must prove exhaustive handling of the canonical fields. A custom settings-description language is deferred unless the shared schema cannot express a concrete required projection.
