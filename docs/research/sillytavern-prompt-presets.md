# SillyTavern prompt preset research

Source: local `D:\Projects\SillyTavern`, commit `b1ef254f78b69bdf20d64421cc77d7ff68fff643`.

## Facts

### Prompt-order lists are alternatives selected by one active ID

`PromptManager.getPromptOrderForCharacter` does one `Array.find` by stringified `character_id` and returns that matching entry's `order`, or `[]` when no entry matches ([`PromptManager.js:1200-1208`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:1200)). It does not merge multiple lists. In global mode the manager's default dummy ID is `100000` ([`PromptManager.js:332-339`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:332)); the OpenAI completion configuration overrides that dummy ID to `100001` ([`openai.js:687-691`](D:/Projects/SillyTavern/public/scripts/openai.js:687)). In character mode, character selection sets the active ID to the selected character's real ID and creates that character's default order if absent ([`PromptManager.js:1138-1150`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:1138)). Thus a `100000` list and a `100001` list are endpoint/configuration-specific alternatives in the current source, not additive layers. A native flat recipe should choose the one list relevant to the target endpoint and discard the other list's duplicate entries rather than concatenate them.

### Selection, definitions, and missing entries

`getPromptCollection` iterates only the selected order. For every order entry it resolves the definition by identifier, computes `entry.enabled && shouldTrigger(...)`, skips a missing definition, and adds the prepared definition only when allowed ([`PromptManager.js:1518-1535`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:1518)). A disabled `main` is retained as an empty prepared prompt for relative insertion compatibility ([`PromptManager.js:1524-1533`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:1524)). The prompt definition's own `enabled` field is not consulted here; the order entry's `enabled` is the runtime gate. `isPromptDisabledForActiveCharacter` likewise reads only the matching order entry ([`PromptManager.js:949-952`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:949)).

During sanitization, orphaned order references are removed ([`PromptManager.js:1024-1035`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:1024)), so an unlisted prompt definition is inert). Missing built-in system definitions are separately re-added from `chatCompletionDefaultPrompts` ([`PromptManager.js:1042-1058`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:1042)), but they still need an order entry to be selected into the prompt collection.

### Built-in markers, authored built-ins, roles, and depth

The built-in definition table distinguishes authored system prompts from structural markers: `main`, `nsfw`, and `jailbreak` are system prompts with content; `enhanceDefinitions` is a system prompt with content and `marker: false`; character description/personality/scenario/persona, world-info, chat history, and dialogue examples are marker prompts ([`PromptManager.js:2000-2081`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:2000)). The default order places `enhanceDefinitions` disabled while the other listed entries are enabled ([`PromptManager.js:2087-2140`](D:/Projects/SillyTavern/public/scripts/PromptManager.js:2087)). These identifiers are ordinary selected entries, but assembly gives `nsfw` and `jailbreak` a dedicated system-prompt pass, then adds relative authored prompts, then adds `enhanceDefinitions` if present ([`openai.js:1218-1244`](D:/Projects/SillyTavern/public/scripts/openai.js:1218)). Therefore duplicate 11/79 entries with only `enhanceDefinitions` enabled state changed represent differing recipes/configuration, not an implicit second layer.

When generated system prompts are merged, prompt-manager definition fields override generated prompt injection position, depth, order, and role when present ([`openai.js:1461-1480`](D:/Projects/SillyTavern/public/scripts/openai.js:1461)). In-chat injections are processed from depth `0` through max depth; at each depth order groups sort numerically descending, then roles are emitted in `system`, `user`, `assistant` order, and extension in-chat text is joined into each role group ([`openai.js:810-857`](D:/Projects/SillyTavern/public/scripts/openai.js:810)). The resulting role messages are inserted at `i + totalInsertedMessages`, then the message array is reversed ([`openai.js:859-866`](D:/Projects/SillyTavern/public/scripts/openai.js:859)). Preserve authored roles and depth/order fields when importing; do not flatten them into one role or infer order from JSON list position alone.

### Prompt comments

The macro registry defines `//` as a utility comment macro whose handler returns an empty string, explicitly saying it can be used in prompt definitions without being passed to context ([`core-macros.js:281-301`](D:/Projects/SillyTavern/public/scripts/macros/definitions/core-macros.js:281)). It supports multiline scoped form `{{//}}First\nSecond{{///}}` ([same source](D:/Projects/SillyTavern/public/scripts/macros/definitions/core-macros.js:285)). The lexer treats `//` as a macro token and `/` as a closing scoped-macro flag ([`MacroLexer.js:52-70`](D:/Projects/SillyTavern/public/scripts/macros/engine/MacroLexer.js:52)); scoped processing recursively reparses nested content ([`MacroCstWalker.js:900-945`](D:/Projects/SillyTavern/public/scripts/macros/engine/MacroCstWalker.js:900)). Thus inline comments, multiline scoped comments, and nested macros are parsed and removed from generated context; authored source text remains in the stored prompt definition until macro resolution.

## Narrow import recommendation

For DitzyTavern's native flat recipe, import one selected SillyTavern order list only: use the list for the target completion endpoint (in this source OpenAI uses dummy ID `100001`; generic/global manager default is `100000`). Resolve definitions by identifier, retain only order entries whose definitions exist, and use order-entry `enabled` as the effective enabled state. Keep the order list's sequence, authored role, injection depth, and injection order. Treat `main`, `nsfw`, `jailbreak`, and `enhanceDefinitions` as authored built-in definitions with their existing semantics; treat marker identifiers as placement anchors. Preserve `{{//...}}` comments in authored content and strip them only during macro expansion. The 11-entry and 79-entry lists in Marinara should not be concatenated absent an explicit user choice of which recipe is intended.

## Uncertainty

The generic `PromptManager` constructor defaults to dummy ID `100000`, while the OpenAI configuration passes `100001`; other completion backends may provide their own configuration. The exact meaning of a particular sample's two lists therefore depends on which endpoint/configuration consumed it. The source establishes selection-by-ID and no additive merge, but not that every external preset's 100000/100001 pair has the same authorial intent.
