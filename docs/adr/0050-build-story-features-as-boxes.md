# Build story features as Boxes

Story features that keep their own state and feed Generations are built as Boxes. A Box is a compiled-in unit with an opaque state and a fixed set of optional hooks. It turns state into prompt items, may resolve Moves the human attached to a Message, may read finished prose in the background, and may render its own window. The host stores, orders and routes Box data and never interprets it: the host owns selection, ordering and provenance, the Box owns what its state means, and the writer owns deliberate departures through Writer overrides. The Author Note, Memory, the World Clock, the Race and the Phone are the first Boxes. Before this, each feature added its own Conversation column, preset reference, unique index, compiler branch and job machinery.

A Box record is the resolved outcome retained with its Variant, never an operation to execute again. This extends [ADR-0038](0038-carry-macro-state-through-selected-variants.md) from Macro State to every Box. State is the Box's fold over the effective records of selected Variants in Message order, where effective means the Writer override if one exists and the automatic record otherwise. Changing an earlier selection or overriding an earlier record never re-evaluates, invalidates or excludes later records. A Variant's prose and its records remain a consistent pair, and the discontinuity appears at the edited point, as it already does for prose. To re-resolve a later turn against new upstream state, the writer swipes it: the Sibling reuses its Message's Moves and inherits the selected sibling's seed, and re-roll is a Sibling with a new seed. Writer overrides never rewrite prose, and the writer reconciles any discrepancy. Completed Variants keep their captured inputs. Background results that arrive later change only current derivation and, through fingerprints, unsent previews, consistent with [ADR-0042](0042-send-the-inspected-prompt-plan-without-reassembly.md).

Box data lives only in namespaced `(owner, namespace, key, value)` tables at six scopes: library, Character, Participant, Conversation, Message and Variant. The namespace is `box:<id>`. The host performs every Message and Variant write from Moves and hook results, so provenance and Writer overrides stay host-owned. Boxes cannot add tables. A domain that needs relational queries remains in-tree code that owns its tables under [ADR-0018](0018-keep-sql-with-domain-invariants.md); Lorebooks and, until its full port, Memory's collections are such domains. Character data is copied into Participant data when a Character seeds a Participant, following the Definition copy rule.

A Box enters the Prompt Plan only through a preset block whose reference is `box:<id>`, at most one per Box per preset, as [ADR-0036](0036-introduce-prompt-presets-as-assembly-recipes.md) keeps the preset as the assembly recipe. This replaces the `author-note` and `memory` references and their single-block indexes, and moves the Author Note out of its Conversation field from [ADR-0048](0048-add-a-chat-wide-author-note-through-a-preset-slot.md). Boxes compose only through the Prompt Plan: no Box reads another Box's output from the same turn, so every Box advances in parallel.

## Considered Options

- Provider tool calling as the way features act: rejected because Chat Completions requests block `tools`, it requires multi-step Generations, and roleplay-tuned models use tools poorly.
- Story state as one mutable Conversation-wide value: rejected because it breaks on swipe, as ADR-0038 already found for Macro State.
- Invalidating or excluding records downstream of an edit: rejected because it leaves state at the tail out of step with the visible prose, and Messages have no narrative branches from which to continue.
- Causal dependency hashes on every record: rejected because the system deliberately does not act on causal dependence.
- A universal delta or snapshot record format: rejected because record granularity belongs to the Box. The Race records full post-Stretch state, Memory independent claims, the World Clock facts about one passage.
- An append-only history of Writer overrides: rejected because reset becomes ambiguous after repeated edits. One overlay per record is simpler.
- Box-to-Box dependencies with a scheduler: rejected because the Prompt Plan is enough as a composition boundary and keeps Boxes parallel.
- Host-enforced purity: rejected because Memory recall needs I/O. Capture plus fingerprint gives the same inspection guarantee.
- A runtime loader, sandboxing, or MCP Apps as the wire: deferred until a Box comes from outside the repository. The contract is plain data, so it does not block them.
