# Admit Images natively into Messages and Definitions

Writers can place Images in Message Variants, Character and Participant Definitions, Openings, and Macro Variable values. Generating models receive the pixels, not a description. This supersedes the text-only clause of [ADR-0001](0001-focused-reimplementation.md) for image input only; image generation, audio, and tool calls stay excluded. It also supersedes the image and `modalities` rejection in [ADR-0015](0015-hide-model-transport-in-one-deep-module.md). Native input was chosen over describe-once captioning, where a vision model writes a stored description at upload and every later step stays text. Captioning fixes a lossy text version at upload, so a model can never look again at a map, screenshot, or document page, and those are scenarios writers use.

Prompt Images share the content-addressed SQLite image store that [ADR-0045](0045-store-portraits-as-content-addressed-definition-images.md) introduces for Portraits. A Portrait is one kind of reference to an Image, and an Image Reference in text is another. At startup, mark-and-sweep scans all persisted owners, including Macro State on non-selected branches and Active Generation captures, to collect referenced hashes. It clears `orphaned_at` for referenced Images, marks previously unmarked unreferenced Images with the startup time, and deletes Images orphaned for more than 24 hours. A Reference saved while its Image was missing protects it after re-upload. Writes maintain no reference index. Images are uploaded through one endpoint and start orphaned. Commands carry hashes only; unsent drafts can adopt an upload during the grace period. SQLite keeps bytes, owner data, and backup together. This replaces the original same-transaction deletion and inline-byte rule.

The server accepts PNG, JPEG, WebP, and GIF, identified by magic bytes, up to 20 MB. It never resizes or transcodes them. Before hashing, ingest strips metadata losslessly with `@uwx/exif-be-gone-web`: EXIF, XMP, IPTC, and comments, plus PNG text chunks including Tavern Card data. ICC profiles, pixel data, and GIF animation are kept. Dimensions are read from the container header without decoding. Stripping is deterministic, so the same upload always produces the same Image. Re-encoding was rejected because it makes screenshots and document pages unreadable and breaks deduplication across uploads. Sending exact bytes was rejected because phone photos carry GPS coordinates to the provider.

Stored text carries Image References as Markdown image syntax: `![name](image:<sha256>)`. The hash is the only identity; the name is display text, sanitized so it survives a Markdown link. Prose rendering resolves only the `image:` scheme and never fetches remote image URLs, including ones a model writes. Composer, Variant edit, Definition, Opening, and Macro Variable editors use CodeMirror 6. Each Reference is drawn as an atomic chip over text that stays the document itself. Tiptap and Lexical were rejected because their tree documents need a Markdown round trip that normalizes the writer's text, which breaks ADR-0007's exact-raw-text rule for Example Dialogue and prose full of `*actions*`, quotes, and macros.

A Portrait never enters a Prompt Plan. Showing it to a model takes an Image Reference to the same Image in Definition text. Otherwise every Character with artwork would silently add an Image to every Generation.

References are resolved after macro expansion anywhere in the Prompt Plan, so a Macro Variable holding a Reference gives each branch its own visual state through ADR-0038 Macro State. Prompt Preset and Lore Entry text cannot author References, because their JSON exports carry no bytes. Prompt Plans, Generation checkpoints, and Active Generation records hold References only. The Model Client loads bytes while building the request and sends them as base64 data URLs, because a provider cannot fetch from a loopback server. Every text-only consumer, including the Lore Scan Window, Semantic Trigger judging, Memory extraction, embeddings, and the Estimation transcript, reads each Reference as its Image Anchor `[Image: name]`. No hash ever reaches a model as text.

On the Chat Completions wire, the anchor text precedes an image part at the Reference's position. Chat Completions accepts image parts only in `user` messages. Images in `system` or `assistant` messages are therefore placed in a `user` message immediately after them, which is the Format-native placement ADR-0015 permits. This covers Definition slots with those roles and Human-authored Messages that ADR-0035 sends as model writing after a seat moves. The one exception is an assistant prefill whose own text contains an Image: the prefill must be last, so that Generation is refused.

A Generation Setting decides which References to a repeated Image send it: the first occurrence, the last occurrence (the default), or every occurrence. It is computed after budget eviction, and the settings UI explains the trade-offs. First keeps the request prefix stable for provider prompt caching. Last places the Image where the writer most recently asked the model to look, but moves it forward on every re-reference and invalidates cached prefixes from its earlier position. Every sends all copies at full cost. The Token estimate counts each sent Image as `w·h/750` after notionally fitting its long edge to 1568 px. This deliberately conservative formula is shared by every Format, and Images are added to their entry's cost, so eviction still removes whole entries.

Image support is never inferred from a provider error. When a Generation fails before output and its plan contained Images, the provider's message is shown with actions to mark the model as a Text-only Model, optionally retrying. The mark is stored per model ID on the Connection Profile and can be toggled back in the model picker. Text-only Models receive Image Anchors without Images. A Reference whose Image is missing from the store sends its anchor only and raises a warning in Prompt inspection and Generation Details.
